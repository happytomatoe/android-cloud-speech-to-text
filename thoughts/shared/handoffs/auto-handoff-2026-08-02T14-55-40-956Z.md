## Learnings

### Samsung Galaxy A32 5G specifics:
1. **IME enable via ADB doesn't work**: `adb shell ime enable` fails. Must use:
   ```
   adb shell settings put secure enabled_input_methods "$(current_list):com.example.whispertoinput/.WhisperInputService"
   ```

2. **Samsung Settings UI differs from stock Android**: No `search_action_bar_title` resource ID. Use app's own `MainActivity` + `field_debug_output` EditText instead.

3. **App's test file mode** (`USE_TEST_FILE=true`):
   - First broadcast tap → UI shows "recording" (nothing records)
   - Second broadcast tap → sends file at `TEST_FILE_PATH` to backend API
   - Default path: `/sdcard/test-speech-loud.wav` — **fails on real devices** (EACCES)

4. **Real device storage permission**: App doesn't request `READ_EXTERNAL_STORAGE`. WAV must go to app-private storage via `run-as`:
   ```
   adb push file.wav /data/local/tmp/
   adb shell "run-as $PACKAGE cp /data/local/tmp/file.wav files/test-speech-loud.wav"
   ```
   DataStore `test-file-path` must use absolute path: `/data/user/0/com.example.whispertoinput/files/test-speech-loud.wav`

5. **DataStore refresh**: After writing DataStore via `run-as`, must `am force-stop` the app to pick up changes.

6. **IME must be set BEFORE showing keyboard**: `ime set` must happen before tapping EditText, otherwise Samsung IME appears and broadcast doesn't reach our service.

7. **Broadcast detection**: In test file mode, logcat only shows `onReceive: action=...` — no "Recording started" message. `wait_for_recording()` must check for `onReceive` instead.

8. **Deepgram key expired**: `f97f6e1e42b697792bfe1867f7679fdeaace4de8` → `INVALID_AUTH`. New key: `11f60d2a5f21c0a181961250804ba123e3261107`
