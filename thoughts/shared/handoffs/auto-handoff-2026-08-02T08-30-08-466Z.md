## Learnings

1. **BIND_KEY_SERVICE permission is required**: The key-manager service declares `android:permission="com.example.keymanager.BIND_KEY_SERVICE"` which means any client app must declare `<uses-permission android:name="com.example.keymanager.BIND_KEY_SERVICE" />` in its manifest. Without it, `bindService()` returns false silently.

2. **Broadcast receiver fires before keyboard view is created**: The `TOGGLE_RECORDING` broadcast is received in `WhisperInputService.toggleReceiver`, which calls `whisperKeyboard.tryStartRecording()`. But if the keyboard view hasn't been created yet (no `onCreateInputView` called), the views like `labelStatus`, `buttonMic` are null, causing a NullPointerException at `WhisperKeyboard.kt:301` in `setKeyboardStatus()`.

3. **Key-manager binding is lazy**: The log shows "Key Manager app not installed or not accessible" on first attempt, but "Connected to Key Manager service" later. This is because `bindAttempted` flag prevents retry, but the binding succeeds when the service is started by another means (e.g., opening key-manager app).

4. **Samsung keyboards may override IME setting**: The default IME kept reverting to `com.samsung.android.honeyboard/.service.HoneyBoardService`. Must explicitly set whisper as default before testing.

5. **`kill -9` is forbidden in this sandbox**: Cannot kill stuck processes.
