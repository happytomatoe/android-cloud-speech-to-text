## Learnings
### Root Cause
Android permissions are granted at install time, not at runtime (for normal-level permissions). When whisper-to-input was installed FIRST (18:10:19), the permission `com.example.keymanager.BIND_KEY_SERVICE` didn't exist yet (because keymanager wasn't installed until 18:29:07). Android silently ignores permission requests for permissions that don't exist.

### The Workaround (from Stack Overflow research)
**Both apps can declare the same `<permission>` element.** If whisper-to-input ALSO declares:
```xml
<permission
    android:name="com.example.keymanager.BIND_KEY_SERVICE"
    android:protectionLevel="normal"/>
```
...then the permission exists at install time regardless of which app is installed first. However, since Android 5.0+, only apps signed with the same certificate can declare the same permission. Since these are separate apps with different signing keys, this workaround won't work directly.

### Key Android Permission Facts
1. Permissions are granted at install time only
2. If a permission doesn't exist when an app is installed, the `<uses-permission>` request is silently ignored
3. Android does NOT retroactively grant permissions when the permission-defining app is installed later
4. Reinstalling the requesting app triggers Android to re-evaluate all permissions
